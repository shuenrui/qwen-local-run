## 5. Non-negotiables you must not break

From `AGENTS.md`, and all of them are asserted by the browser suite:

1. **Every number carries a provenance tier.** A number with no source is
   deleted, never downgraded.
2. **Tiers never blend.** `box` / `forum` / `vendor` stay separate in every view.
3. **Negative results stay visible.** Caveats and known failures are promoted,
   not buried.
4. **No quality leaderboard.** Canaries from different harnesses are never
   aggregated. Speed sorting carries a non-dismissible disclosure.
5. **`site/index.html` is generated.** Change `site_src/`, `build.py` or the
   data and rebuild.
6. **Never push to `origin`** — it is a third party's repo. Pushes go to `mine`.
7. **No unconditional "fits" verdict anywhere.** Compatibility verdicts exist
   only on `#/hardware` and must state their full arithmetic and assumptions.
8. **Compare never declares a winner.**
9. **Model capability, runtime support and task quality are three separate
   claims** with three separate evidence requirements.
10. **Do not weaken `validate.py` to make data pass.**

### Presentation rules that are easy to break accidentally

- A single-stream tok/s figure always wins the headline. Aggregate throughput is
  never promoted into that slot and always states its concurrency. On this
  dataset aggregate runs up to **17×** the single-stream figure for the same
  recipe.
- **No bare numbers.** Every value carries metric, condition and provenance.
- Never pass an HTML entity through `esc()` — it escapes the ampersand and the
  entity leaks to the page. Literal Unicode only.
- Unrecorded fields render `not recorded`, never `0`, `—`, `N/A` or blank.
- `kv_bytes_per_token` exists on **1 of 22** model families, so a KV-cache
  allowance is computable for exactly one. It is never estimated from parameter
  count.

## 6. Routing is hash-based on purpose

`ifhost publish` accepts **exactly one HTML file** served at `/`, so a real
sub-path would 404. `#/`, `#/recipes`, `#/hardware`, `#/compare`,
`#/models/<id>`, `#/recipes/<id>` are the canonical shareable URLs. A path shim
in `boot()` rewrites the documented paths to hashes if the site ever moves to a
host with directory rewrites. Do not "fix" this into history-API routing without
changing hosts first.

## 7. How to verify anything

```bash
bash directory/tools/install_verify_env.sh   # once per checkout
python3 directory/check.sh                   # validate -> links -> build -> browser
```

Current state: **0 errors, 1 warning, all source URLs reachable, 207 browser
checks passing.**

- The **1 warning** is pre-existing and not mine:
  `hardware/gpu-multigpu-72gb: no device spec`. It comes from the device-spec
  schema added in `e51ab8c`.
- **`check_links.py` is flaky under repeated runs.** It sweeps ~150 URLs with no
  backoff and HuggingFace starts returning `429`. I saw all 32 HF URLs fail as
  `429` while each returned `200` when fetched individually a minute later. If
  link rot fails, check whether every failure is `429` before believing it.
  Fixing that (backoff + retry on 429) is a real small task nobody has done.

The browser suite is the main safety net. It drives real clicks, typing and
navigation, recomputes the four confidence dimensions against the inlined
dataset for every setup, and asserts the presentation rules in §5 directly. If
you change a row, a verdict or a sort, expect it to catch you.
